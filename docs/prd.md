# Product requirements: AI Visibility Checker

Status: v1 built and public on GitHub (26 Oct 2026). Not yet deployed.
Owner: Steve Mathew.

## 1. Summary

A free web tool. You paste a URL, and in a few seconds it tells you how likely AI answer engines (ChatGPT search, Perplexity, Google AI Overviews, Claude) are to find, read and cite that page. You get a score out of 100, a score for each of five areas, and a ranked list of fixes with paste-ready snippets. It's built the way a growth team would build a lead magnet: the full value is free and needs no sign-up, and the ask (a monthly re-check by email) comes after the value.

## 2. Problem

Search is turning into answers. When an engine replies with a paragraph and three citations, the brands that aren't cited get nothing, and most marketers have no way to tell why they're missing. The usual causes are invisible in normal SEO tools:

- robots.txt blocking the specific bots that fetch pages for live answers (OAI-SearchBot, PerplexityBot, Claude-SearchBot), often by accident or copied from a "block AI" template.
- Pages whose text only appears after JavaScript runs, which most AI crawlers don't execute.
- No structured data, so engines can't tell who the business is or what the page is.
- Content written as long intros instead of short, quotable answers under clear headings.

## 3. Goals and non-goals

**Goals (v1)**

1. Give an accurate, explainable read on a single page in under 10 seconds.
2. Rank fixes so the first one is the best use of the next hour.
3. Be honest about what's known and what isn't (llms.txt, citations vs citability).
4. Make results shareable by URL so a marketer can hand them to a developer.
5. Work with no API key and no database. The AI summary is a bonus layer.

**Non-goals (v1)**

- Measuring whether a page is actually cited today (needs live queries against the engines; see phases.md, Phase 3).
- Crawling a whole site.
- Accounts, saved history, billing.
- Ranking or traffic data.

## 4. Users

| Persona | Situation | What they need |
| --- | --- | --- |
| Marketing manager at an SMB or startup | Told "we need to show up in ChatGPT", no technical team on call | A clear score, plain-English reasons, a short list of what to ask the developer for |
| Founder or solo operator | Runs their own site on Webflow, WordPress or Shopify | Fixes they can paste in themselves (robots.txt lines, JSON-LD) |
| Developer or agency SEO | Gets a link from the marketer | The evidence behind each check, and exact snippets |
| Growth team (the tool's owner) | Wants qualified leads | Email capture at the right moment, and a shareable artefact that spreads |

## 5. User stories

1. As a marketer, I paste my URL and see within seconds whether AI engines can reach my page at all.
2. As a marketer, I see a one-sentence verdict I can repeat in a meeting.
3. As a marketer, I see which fix to do first and roughly how much effort it is.
4. As a developer, I open a shared link and see the same report with the evidence and snippets.
5. As a founder, I copy a robots.txt block or JSON-LD snippet that already contains my real site name and URL.
6. As any user, I understand that blocking training bots is a choice and doesn't stop citations.
7. As a visitor who isn't ready to test a site yet, I can open a sample report.
8. As a returning user, I can leave my email to have the page re-checked monthly (v1: demo only, nothing stored).

## 6. Functional requirements

| ID | Requirement | v1 |
| --- | --- | --- |
| FR-1 | Accept a URL with or without scheme; normalise to https | Done |
| FR-2 | Fetch the page server-side, plus robots.txt, /llms.txt and the sitemap, in parallel | Done |
| FR-3 | Evaluate robots.txt for 14 crawlers, split into answer, search and training bots | Done |
| FR-4 | Run 29 rule-based checks across five weighted categories | Done |
| FR-5 | Cap the overall score for hard blockers (noindex 25, answer bots blocked 35, JS-only 45) | Done |
| FR-6 | Every warn or fail check carries a fix: why, how, impact, effort, and a snippet where useful | Done |
| FR-7 | Rank fixes by impact × points lost × category weight × effort multiplier | Done |
| FR-8 | Shareable report URL `/report?url=...` | Done |
| FR-9 | Sample report at `/report?demo=1`, generated by the real engine | Done |
| FR-10 | Optional AI summary and rewrites via one Claude call; degrades to a note without a key or on any error | Done (untested with a live key) |
| FR-11 | Clear error states: invalid URL, private host, fetch failed (with status), not HTML, rate limited | Done |
| FR-12 | Email capture component after the report | Demo only |

## 7. Non-functional requirements

- **Speed.** Audit returns in 1 to 8 seconds for normal pages. Hard timeouts: 10 s for the page, 5 to 6 s for side files, 30 s route limit.
- **Safety.** The fetcher must not reach private networks or cloud metadata (SSRF guard on every redirect hop), only ports 80/443, 8 MB body cap.
- **Cost.** Rule-based audit costs nothing per run. The AI summary is one call per report view; it must be rate-limited and should be cached per URL before wide launch.
- **Honesty.** No copy that promises inclusion in AI answers. Unproven tactics are labelled as such.
- **Accessibility.** Keyboard reachable, visible focus, labelled inputs, `aria-live` loading state, contrast that holds in light and dark mode, reduced-motion respected.
- **Responsive.** No horizontal scroll at 375 px.

## 8. Success metrics (once deployed)

| Stage | Metric | First target |
| --- | --- | --- |
| Acquisition | Audits run per week | 200 |
| Activation | Share of visitors who run an audit | 40% |
| Value | Share of reports where at least one fix snippet is copied | 25% |
| Virality | Share-link opens per report | 0.3 |
| Capture | Email sign-ups per completed report | 5% |
| Quality | Reports flagged wrong by users | under 2% |

Targets are starting guesses to be replaced with real baselines after two weeks of traffic.

## 9. Risks

| Risk | Mitigation |
| --- | --- |
| Weights are judgement, not measured | Say so in the README and UI; validate once citation tracking exists (Phase 5) |
| Sites block our fetcher (403) | Clear message, no guessing; never spoof a real crawler's user agent |
| Some sites serve different robots.txt to real crawlers | Documented limitation |
| AI summary cost spikes from a viral share link | Per-IP rate limit now; per-URL cache before launch |
| AEO best practice shifts quickly | Checks are small, isolated files; sample report regenerates from the engine |
